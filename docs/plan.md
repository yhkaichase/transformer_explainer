# 콘텐츠 계획

## 목표

트랜스포머를 **주니어 엔지니어와 임원**이 30분 안에 이해할 수 있게 설명하는 한국어 웹 페이지.
참고 프로젝트 [Transformer Explainer](https://github.com/poloclub/transformer-explainer)보다 쉬워야 한다.

### 참고 프로젝트와 다른 점

| 항목      | Transformer Explainer (참고)             | 이 프로젝트                                            |
| --------- | ---------------------------------------- | ------------------------------------------------------ |
| 대상      | 비전문가~학습자                          | 임원(비유·결과) + 주니어 엔지니어(수식·구조)           |

## 실시간 파이프라인 (2차 피드백 반영)

사용자 피드백: "참고 프로젝트보다 너무 단순하다. 글은 줄이고, 입력 토큰을 바꾸면 값이 산출되게(active)."

- 참고 프로젝트는 브라우저에서 실제 GPT-2 를 내려받아 실행한다. 회사 환경(외부 접속 제한, 수백 MB 다운로드)에서는 부담이므로,
  대신 이 저장소에서 **작은 트랜스포머를 직접 학습**해 가중치(약 11만 파라미터, fp16 313 KB)를 페이지에 내장했다.
  어떤 입력을 넣어도 토큰 → 임베딩 → 어텐션 → 다음 글자 확률이 브라우저에서 실시간으로 계산되고, 단일 HTML 파일로도 오프라인 동작한다.
- 모델: 문자 단위 디코더 전용(pre-LN, 학습된 위치 임베딩, ReLU FFN, 임베딩 공유), 3층 × 3헤드, d_model 48, 문맥 64.
  학습 데이터는 이 페이지의 본문(한국어·영어 34,279 글자). 학습: `scripts/train_tiny_model.py`(JAX, CPU 약 4분), 손실 6.32 → 0.71.
- 정확성: TypeScript 추론(`src/lib/tinyTransformer.ts`)이 학습 코드가 내보낸 기준값(상위 5개 확률, 어텐션 행렬)과 소수 셋째 자리까지 일치함을 테스트로 검사한다.
- 화면: 새 첫 섹션 "직접 넣어 보기". 본문 문단은 임원용에서 "자세히 읽기"로 접히고, 한 줄 요약·비유·데모만 보인다.
- 한계(화면에 밝힘): 크기가 작아 본문과 비슷한 글에서만 그럴듯하게 이어 쓴다. 실제 GPT-2 의 값은 A안(사전 계산 JSON)으로 별도 제공한다.
- 대안으로 남겨 둔 것: transformers.js 등으로 실제 GPT-2 를 브라우저에서 실행하는 방식. 네트워크와 다운로드 용량이 허용되는 환경에서만 의미가 있다.

## 시뮬레이터 페이지 (3차 피드백 반영)

사용자 피드백: "임원용/엔지니어용 구분은 필요 없다. 참고 프로젝트처럼 prefill-decode 각 단계에서 어텐션과 FFN 에 가중치가 어떻게 적용되는지 구조적으로 아름답게. 글은 없어도 된다. 새 파일 transformer-simulator.html."

- 두 번째 페이지 `simulator.html` (`src/simulator/`). 설명 글 없이 구조도와 수식만 있고, 청중 모드가 없다.
- 한 화면에 가로로: 토큰 → E[id] + P[pos] → [층 ℓ] LN₁ → W_Q·W_K·W_V 히트맵 → Q·K·V 띠(헤드 경계 표시) → 헤드별 어텐션(선택 헤드 크게 + 작은 그림) → A·V concat → W_O → 잔차 → LN₂ → W₁ → ReLU → W₂ → 잔차 → LN_f → Eᵀ 로짓 → softmax → 다음 토큰.
  모든 값은 내장 소형 모델의 실제 계산이며 캔버스 히트맵으로 그린다. 마우스를 올리면 값이 보인다.
- 단계 스테퍼 18단계(← → 키, 자동 재생 0.5×~4× 배속, 마지막 단계 뒤 토큰 이어 쓰기 옵션). 현재 단계의 요소만 강조하고 나머지는 흐리게. 수식과 형상([T×48]·[48×48] 등)을 함께 표시.
- Prefill: 프롬프트 토큰 전체를 한 번에 계산. Decode: 새 토큰 1개만 계산하고 앞 토큰의 K·V 는 캐시로 표시(흐리게). 새 토큰에 배지.
- 초점 토큰: 토큰이나 띠의 행을 누르면 그 위치의 계산을 아래 카드에서 수식 그대로 보여 준다 (h · W_Q + b_Q = q, 점수 표, ReLU 로 0 이 된 자리 등).
- 빌드: `npm run build` 가 두 페이지를 만들고 `npm run build:single` 이 `transformer-simulator.html` 도 만든다.

## DeepSeek-V4.1-Flash 시뮬레이터 페이지 (4차 피드백 반영)

사용자가 저장소에 넣은 `DeepseekV4.1_manual.docx`(2026-09-21, "DeepSeek-V4.1-Flash의 KV cache가 토큰당 890 B인 이유")를 근거로,
트랜스포머 시뮬레이터와 같은 방식(내장 축소 모델이 실제로 계산, 단계 스테퍼, 초점 토큰 수식, prefill/decode)으로 V4.1-Flash 의 동작을 보여 주는
세 번째 페이지 `DCv4.1-simulator.html` 을 만들었다.

- 매뉴얼에서 가져온 구조: CED(encoder 20 + decoder 20, decoder KV 는 L19 출력에서 투영, prefill 에서 decoder 는 마지막 128토큰만),
  CSA2 세 모드(Full L2·L8·L14·L20, Reindex L24·L28·L32·L36, 나머지 Reuse, L0·L1 SWA 전용), 64 헤드가 512차원 latent 하나를 key·value 로 공유,
  indexer K 128차원과 Top-512, 후보 풀 2,048블록 × 8, SWA 128, main KV 288 B(FP4 + E4M3 scale) · indexer K 68 B(MXFP4),
  890 B = (288 + 68) × (3 × ½ + 1), MoE shared 1 + routed 6/384, decode 1스텝 읽기량(1M: indexer K 174 MB, main KV 5.6 MB, SWA 3.0 MB).
- 축소판(`scripts/train_tiny_dsv41.py`): 10층(encoder 5 + decoder 5), 헤드 4 × latent 16, 인덱서 2 × 8, Top-4, 윈도우 8, 후보 풀 2 × 4,
  MoE 1 + 2/8, FP4 scale 그룹 8채널. 모드 배치는 L0 swa, L1·L3 full(m=2), L2·L4 reuse, L5 full(m=1, CED), L6·L8 reuse, L7·L9 reindex.
  학습은 dense 워밍업 → 희소 Top-K → FP4 QAT 순서이고, 인덱서는 V3.2 방식대로 main attention 분포에 KL 로 정렬한다.
- 브라우저 구현(`src/lib/tinyDsv41.ts`)은 학습 코드와 같은 순서로 계산하고, 양자화 규칙까지 글자 그대로 같다. 기준값 테스트가 Top-K·후보 풀·전문가 선택의 일치까지 확인한다.
- 화면: 층 배치 패널(모드 색, KV 생성 층, CED 화살표) → 선택한 층의 다섯 줄(Query·SWA / global KV / 인덱서·Top-K / 두 분기 어텐션 / MoE) → 출력 → KV cache 카드.
  Reuse·Reindex 층에서 물려받는 값은 점선으로, 없는 단계는 취소선으로 표시한다. prefill 에서 decoder 를 지나지 않는 토큰에는 "enc만" 표시가 붙는다.
- 밝힌 단순화: 크기, 문자 토큰과 절대 위치 임베딩(RoPE 대신), 매뉴얼이 가정한 인덱서 점수 함수와 SWA 의 query 공유, MoE 라우터 세부(sigmoid + 편향),
  DSpark·persistent KV 미구현. 실제 모델 수치는 모두 매뉴얼에서 가져왔고, 매뉴얼이 2차 자료라고 밝힌 값(헤드 64, latent 512 등)은 그 성격 그대로 적었다.
- 열린 질문: 매뉴얼이 확인하지 못했다고 한 부분(SWA 분기의 별도 투영 여부, 인덱서 헤드 수, d_model)은 실제 리포트(arXiv 2609.19969)로 확인되면 반영한다.
  이 세션에서는 arXiv·Hugging Face 접속이 막혀 있어 매뉴얼 이외의 출처로 교차 검증하지 못했다.

## 설계 원칙

1. **비유 먼저, 수식은 선택.** 모든 섹션은 "비유로 이해하기" 콜아웃으로 시작한다. 수식은 엔지니어용에서만.
2. **한 섹션에 한 가지 생각.** 섹션 제목이 곧 그 생각이다 ("서로 참고하기: 어텐션").
3. **검증된 사실만.** 출처가 확인되지 않은 숫자·주장은 쓰지 않는다. 기본 출처는 Vaswani et al. 2017.
4. **단순화는 밝힌다.** 데모가 실제 모델과 다르면 화면에 적는다.
5. **임원에게는 의사결정 관점을 하나씩.** 예: 어텐션 비용은 길이의 제곱, 온도 설정이 결과 성격을 바꿈.

## 섹션 구성과 상태

| #   | id        | 제목                             | 상태  | 인터랙티브 요소 (계획)                                                      |
| --- | --------- | -------------------------------- | ----- | --------------------------------------------------------------------------- |
| 1   | intro     | 트랜스포머, 한 문장으로          | ready | 전체 흐름 6단계 스테퍼 (완료)                                               |
| 2   | tokens    | 글자를 숫자로: 토큰과 임베딩     | ready | 토크나이저 데모 (완료), 임베딩 벡터 막대 시각화                             |
| 3   | position  | 순서를 기억하기: 위치 정보       | ready | 사인·코사인 위치 패턴 히트맵 (완료)                                         |
| 4   | attention | 서로 참고하기: 어텐션            | ready | 계산 과정 따라가기 (완료), 실제 값 히트맵 컴포넌트 (완료, 데이터 파일 대기) |
| 5   | multihead | 여러 관점으로 보기: 멀티헤드     | ready | 헤드별 작은 그림 비교 컴포넌트 (완료, 데이터 파일 대기)                     |
| 6   | ffn       | 혼자 생각을 정리하기: 피드포워드 | ready | 토큰별 독립 처리 + ReLU 계산 (완료)                                         |
| 7   | stack     | 반복해서 깊어지기: 층 쌓기       | ready | 층 수 슬라이더 + 잔차 연결 도식 (완료)                                      |
| 8   | output    | 다음 단어 고르기: 확률과 온도    | ready | **온도 슬라이더** 확률 막대 + 뽑기 데모 (완료)                              |
| 9   | training  | 어떻게 배우나: 학습              | ready | "예측 → 채점 → 조정" 학습 데모 (완료)                                       |
| 10  | summary   | 정리: 1분 요약과 다음 단계       | ready | 1분 요약 카드 + 엔지니어용 다음 단계 (완료)                                 |

## 어텐션 데모의 값을 어디서 가져올 것인가 (결정 필요)

어텐션 히트맵은 이 페이지의 핵심이다. 값의 출처로 세 가지 선택지가 있다.

| 선택지                                                            | 장점                                | 단점                                                    |
| ----------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------- |
| A. 예문 몇 개의 실제 GPT-2 어텐션 값을 미리 계산해 JSON 으로 내장 | 실제 값, 가볍고 빠름, 오프라인 동작 | 예문이 고정됨 (자유 입력 불가), 사전 계산 스크립트 필요 |
| B. 브라우저에서 GPT-2 실행 (참고 프로젝트 방식)                   | 자유 입력, 실제 값                  | 수십 MB 다운로드, 구현 복잡, 임원용 데모로는 무거움     |
| C. 토이 무작위 가중치로 계산                                      | 구현 쉬움                           | 패턴이 무의미해서 오해를 부를 수 있음 (비추천)          |

**추천: A.** 한국어·영어 예문 5개 안팎을 고정하고, 실제 모델의 어텐션 값을 보여 준다. 수식 단계(Q·K → 나누기 → softmax → 가중합)는 `src/lib/math.ts` 의 토이 계산으로 작은 크기에서 따라가게 한다.
사전 계산에는 Python + transformers 가 필요하며, 스크립트와 출력 JSON 을 저장소에 함께 둔다.

**진행 상태**: 사용자의 명시적 선택이 없어 추천안(A)을 가정하고 준비를 마쳤다. 되돌리기 쉽다.

- `scripts/precompute_attention.py`, `scripts/examples.json`(예문 4개 × 2개 언어), `scripts/README.md` 작성.
- `src/lib/attentionData.ts` 가 출력 JSON 을 검사하고, 섹션 4 "실제 모델의 어텐션 보기"(층·헤드·예문 선택, 행 선택) 와 섹션 5 "헤드 비교"(작은 그림 여러 개 + 선택 헤드 확대) 가 이를 그린다.
- 파일이 없으면 두 데모는 만드는 방법을 안내한다. 빌드와 테스트는 데이터 없이 통과한다.
- **남은 일(사용자 PC)**: `pip install -r scripts/requirements.txt` 후 영어는 `--model gpt2`, 한국어는 한국어로 학습된 GPT-2 계열 모델 id 로 스크립트를 실행해 `src/data/attention/en.json`, `ko.json` 을 커밋한다.
  한국어 모델 id 는 이 세션에서 확인하지 못했다(Hugging Face 차단). GPT-2 원본은 영어 모델이라 한국어 문장을 바이트 조각으로 쪼개므로 한국어 예문에는 쓰지 않는다.

## 데모 설계 메모

- 시각화는 dataviz 지침을 따른다: 막대는 한 가지 색(파랑)으로 얇게, 값은 막대 끝에 직접 표시, 모든 값은 표로도 읽힌다.
  히트맵은 파랑(-1) ↔ 회색(0) ↔ 빨강(+1) 다이버징 7단계이며 범례와 숫자 출력이 함께 있다. 색 토큰은 `global.css` 의 `--viz-*`, `--div-*`.
- 온도 데모의 후보 단어와 점수는 예시이며 화면에 그 사실을 밝힌다. softmax 와 온도 계산은 `src/lib/math.ts` 의 실제 구현을 쓴다.
- 위치 인코딩 데모는 원 논문 3.5절 식을 그대로 쓰되 d_model 을 16 으로 줄였다 (화면에 밝힘).
- 어텐션·피드포워드 데모의 Q/K/V 벡터와 가중치는 계산 과정을 보여 주기 위해 정한 예시 숫자다 (화면에 밝힘). 계산 자체는 `math.ts` 의 실제 구현이다.
  어텐션 예시는 문장 순서대로 토큰을 두어 인과 마스크를 켜면 "은행"이 뒤의 "돈"을 보지 못하는 것을 보여 준다.
- 학습 데모는 softmax + 교차 엔트로피의 점수(로짓)에 대한 정확한 기울기(softmax - onehot)로 경사하강 한 걸음을 밟는다.
  실제 모델은 파라미터를 갱신한다는 차이를 화면에 밝힌다.
