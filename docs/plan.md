# 콘텐츠 계획

## 목표

트랜스포머를 **주니어 엔지니어와 임원**이 30분 안에 이해할 수 있게 설명하는 한국어 웹 페이지.
참고 프로젝트 [Transformer Explainer](https://github.com/poloclub/transformer-explainer)보다 쉬워야 한다.

### 참고 프로젝트와 다른 점

| 항목      | Transformer Explainer (참고)             | 이 프로젝트                                            |
| --------- | ---------------------------------------- | ------------------------------------------------------ |
| 대상      | 비전문가~학습자                          | 임원(비유·결과) + 주니어 엔지니어(수식·구조)           |
| 모델 실행 | 브라우저에서 실제 GPT-2 (ONNX Runtime)   | 실행하지 않음. 작은 토이 계산 + 사전 계산 값 (검토 중) |
| 설명 방식 | 모델 구조도를 따라가며 실제 값을 보여 줌 | 비유 → 핵심 문장 → (원하면) 수식. 한 화면에 두 깊이    |
| 언어      | 영어                                     | 한국어 (영어 병기는 열린 질문)                         |
| 스택      | Svelte + Vite + Tailwind + D3            | React + Vite, 외부 UI/CSS 라이브러리 없음              |

## 설계 원칙

1. **비유 먼저, 수식은 선택.** 모든 섹션은 "비유로 이해하기" 콜아웃으로 시작한다. 수식은 엔지니어용에서만.
2. **한 섹션에 한 가지 생각.** 섹션 제목이 곧 그 생각이다 ("서로 참고하기: 어텐션").
3. **검증된 사실만.** 출처가 확인되지 않은 숫자·주장은 쓰지 않는다. 기본 출처는 Vaswani et al. 2017.
4. **단순화는 밝힌다.** 데모가 실제 모델과 다르면 화면에 적는다.
5. **임원에게는 의사결정 관점을 하나씩.** 예: 어텐션 비용은 길이의 제곱, 온도 설정이 결과 성격을 바꿈.

## 섹션 구성과 상태

| #   | id        | 제목                             | 상태  | 인터랙티브 요소 (계획)                                          |
| --- | --------- | -------------------------------- | ----- | --------------------------------------------------------------- |
| 1   | intro     | 트랜스포머, 한 문장으로          | ready | 전체 흐름 6단계 스테퍼 (완료)                                   |
| 2   | tokens    | 글자를 숫자로: 토큰과 임베딩     | ready | 토크나이저 데모 (완료), 임베딩 벡터 막대 시각화                 |
| 3   | position  | 순서를 기억하기: 위치 정보       | draft | 사인·코사인 위치 패턴 히트맵 (완료)                             |
| 4   | attention | 서로 참고하기: 어텐션            | ready | **계산 과정 따라가기** (완료). 실제 값 히트맵은 값 출처 결정 뒤 |
| 5   | multihead | 여러 관점으로 보기: 멀티헤드     | draft | 헤드별 히트맵 나란히 비교                                       |
| 6   | ffn       | 혼자 생각을 정리하기: 피드포워드 | draft | 토큰별 독립 처리 + ReLU 계산 (완료)                             |
| 7   | stack     | 반복해서 깊어지기: 층 쌓기       | draft | 층 수 슬라이더 + 잔차 연결 도식 (완료)                          |
| 8   | output    | 다음 단어 고르기: 확률과 온도    | draft | **온도 슬라이더** 확률 막대 + 뽑기 데모 (완료)                  |
| 9   | training  | 어떻게 배우나: 학습              | draft | "예측 → 채점 → 조정" 학습 데모 (완료)                           |
| 10  | summary   | 정리: 1분 요약과 다음 단계       | draft | 임원용 1분 요약 카드 / 엔지니어용 다음 단계                     |

`status: 'draft'` 인 섹션은 화면에 "초안" 배지가 붙는다. 내용 검수(정확성, 출처, 문장)를 마치면 `ready` 로 바꾼다.

## 어텐션 데모의 값을 어디서 가져올 것인가 (결정 필요)

어텐션 히트맵은 이 페이지의 핵심이다. 값의 출처로 세 가지 선택지가 있다.

| 선택지                                                            | 장점                                | 단점                                                    |
| ----------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------- |
| A. 예문 몇 개의 실제 GPT-2 어텐션 값을 미리 계산해 JSON 으로 내장 | 실제 값, 가볍고 빠름, 오프라인 동작 | 예문이 고정됨 (자유 입력 불가), 사전 계산 스크립트 필요 |
| B. 브라우저에서 GPT-2 실행 (참고 프로젝트 방식)                   | 자유 입력, 실제 값                  | 수십 MB 다운로드, 구현 복잡, 임원용 데모로는 무거움     |
| C. 토이 무작위 가중치로 계산                                      | 구현 쉬움                           | 패턴이 무의미해서 오해를 부를 수 있음 (비추천)          |

**추천: A.** 한국어·영어 예문 5개 안팎을 고정하고, 실제 모델의 어텐션 값을 보여 준다. 수식 단계(Q·K → 나누기 → softmax → 가중합)는 `src/lib/math.ts` 의 토이 계산으로 작은 크기에서 따라가게 한다.
사전 계산에는 Python + transformers 가 필요하며, 스크립트와 출력 JSON 을 저장소에 함께 둔다.

## 데모 설계 메모

- 시각화는 dataviz 지침을 따른다: 막대는 한 가지 색(파랑)으로 얇게, 값은 막대 끝에 직접 표시, 모든 값은 표로도 읽힌다.
  히트맵은 파랑(-1) ↔ 회색(0) ↔ 빨강(+1) 다이버징 7단계이며 범례와 숫자 출력이 함께 있다. 색 토큰은 `global.css` 의 `--viz-*`, `--div-*`.
- 온도 데모의 후보 단어와 점수는 예시이며 화면에 그 사실을 밝힌다. softmax 와 온도 계산은 `src/lib/math.ts` 의 실제 구현을 쓴다.
- 위치 인코딩 데모는 원 논문 3.5절 식을 그대로 쓰되 d_model 을 16 으로 줄였다 (화면에 밝힘).
- 어텐션·피드포워드 데모의 Q/K/V 벡터와 가중치는 계산 과정을 보여 주기 위해 정한 예시 숫자다 (화면에 밝힘). 계산 자체는 `math.ts` 의 실제 구현이다.
  어텐션 예시는 문장 순서대로 토큰을 두어 인과 마스크를 켜면 "은행"이 뒤의 "돈"을 보지 못하는 것을 보여 준다.
- 학습 데모는 softmax + 교차 엔트로피의 점수(로짓)에 대한 정확한 기울기(softmax - onehot)로 경사하강 한 걸음을 밟는다.
  실제 모델은 파라미터를 갱신한다는 차이를 화면에 밝힌다.

## 출처 규칙

- 페이지에 표시하는 링크는 실제로 열리는지 확인한 것만 넣는다 (`src/content/sources.ts`).
- 이 하네스를 만든 원격 세션에서는 네트워크 정책 때문에 github.com 외 대부분의 도메인에 직접 접속할 수 없었다. 아래 목록은 그 세션에서 확인한 방법을 적은 것이다.

| 출처                                              | 확인 방법                       |
| ------------------------------------------------- | ------------------------------- |
| https://github.com/poloclub/transformer-explainer | README 직접 조회                |
| https://arxiv.org/abs/1706.03762                  | 웹 검색 결과에서 제목·번호 확인 |
| https://poloclub.github.io/transformer-explainer/ | 웹 검색 결과에서 확인           |

- 본문에 쓴 구체적 숫자는 모두 Vaswani et al. 2017 에서 가져왔다: d_model = 512, h = 8, d_k = d_v = 64, d_ff = 2048, N = 6, ReLU, Adam, 임베딩-출력층 가중치 공유.
- 아직 출처를 확인하지 못해 **넣지 않은** 주장 (확인되면 추가): GPT-2 의 구체적 크기(층 수, 차원, 어휘 수), "피드포워드 층이 사실을 저장한다"는 해석 연구, RoPE 등 최신 위치 인코딩 방식의 세부.

## 열린 질문 (사용자 결정 필요)

1. ~~**언어**~~: 결정됨. 한국어 기본, 상단 토글과 `?lang=en` 으로 영어. 본문은 `content/ko.ts` 와 `content/en.ts` 에 나란히 두고 문단 수를 맞춘다.
2. **어텐션 값의 출처**: 위 A/B/C 중 선택. 기본은 A 로 진행.
3. **배포**: GitHub Pages 를 쓸지 (저장소 설정에서 Source 를 GitHub Actions 로 지정 필요), 사내 호스팅을 쓸지.
4. **톤과 브랜딩**: 회사 용어나 로고를 넣을지, 중립적으로 둘지.
5. **영어 검수**: 영어 본문은 한국어 본문을 옮긴 초안이다. 원어민 또는 영어 사용 동료의 검수 뒤 `status` 를 `ready` 로 바꾼다.
